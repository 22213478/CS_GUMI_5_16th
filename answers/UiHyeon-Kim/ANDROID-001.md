# 질문 제목

## 한 문장 답변

Activity는 앱에서 하나의 화면을 구성한다.Fragment는 말 그대로 조각이며 Activity 위에서 리스트, 카드 등 컴포넌트 조각이 된다.
그렇기 떄문에 Activity와 Fragment는 별도의 생명주기를 가지며, 별도로 관리해야 한다.

## 개념과 동작 원리

액티비티는 생명주기는 onCreate, onStart, onResume, onPause, onStop, onDestroy 를 가진다.
- onCreate: 화면이 처음 생성될 떄 호출
- onStart: 화면이 사용자에게 보일 때 호출
- onResume: 사용자와 상호작용이 가능할 때 호출
- onPause: 포커스를 잃을 때 호출
- onStop: 홈 같은 버튼으로 화면을 나갈 때 호출
- onDestroy: 화면이 종료될 때 호출

프래그먼트는 사용해본 적이 별로 없어 잘 기억이 나지는 않지만
- onCreateView, onViewCreate, onDestroyView 등
액티비티와 별개의 프래그먼트 생성, 삭제 같은 생명주기를 가진다.

각각의 생명주기에 알맞게 UI를 업데이트 하거나 리소스를 정리해야 한다.
특히 리소스의 경우 사용 후 종료해주지 않으면 메모리 누수가 발생한다.

## Android 또는 실제 개발에서의 적용

Compose가 나온 후 보통 단일 액티비티를 사용하고, Fragment와 비슷한 Composable 컴포넌트를 배치해 UI를 구성한다.

## 장단점과 트레이드오프

액티비티는 화면을 구성할 때 필수로 필요하다. 이게 없으면 화면을 구성할 수 없다.
프래그먼트는 화면에 리스트와 같은 조각을 별도의 생명주기를 가지게 하고 관리하기 위해 사용한다.
프래그먼트의 트레이드오프로는 컴포즈를 예로 들 수 있을 것 같다. 앞서 말한듯 액티비티 위에 UI를 구성하기 위해 사용한다.

## 이어질 수 있는 질문

- 예상 질문: 리소스의 종류에는 무엇이 있고, 이 리소스는 어디서 관리해야 하나요?
- 짧은 답변: 카메라나 비트맵 같은 리소스가 있습니다. 필요에 따라 onStart나 onResume 등의 생명주기에서 실행을 시켜주고, 사용자가 잠깐 해당 리소스를 사용 안한다면 onStop에서 멈춰주고, 필요에 따라 onResume에서 다시 사용하도록 할 수 있습니다. 그리고 해당 액티비티를 나갈 때(해당 리소스가 필요 없어질 때) onDestory에서 완전 종료시켜 메모리 누수를 방지합니다

- 예상 질문: Compose에 대해 아시는 부분이 있으면 간단하게 설명해주세요.
- 짧은 답변: 프론트엔드의 선언형 UI 발전에 따라 Android 에서도 이러한 방식을 체택하게 되었습니다. 선언형 UI는 기존의 XML 방식으로 UI를 그릴 때 필요한 코드를 대폭 줄여 더 간단하고, 알아보기 쉽게 코드를 작성할 수 있습니다.
